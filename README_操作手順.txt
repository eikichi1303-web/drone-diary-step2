DER FLIGHT LOG｜STEP2 工程2・3 確認用

【この一式の内容】
- index.html：機体管理の独立ページ
- styles.css：画面デザイン
- db.js：STEP2データベースの準備
- aircraft.js：機体登録・編集・削除
- sw.js：STEP2専用キャッシュ
- manifest.webmanifest：PWA設定

【重要】
この一式はSTEP1のファイルを含まず、STEP1の公開版を変更しません。
ホーム画面とは接続していません。index.htmlを直接開いて確認します。
本番公開版へ上書きしないでください。

【GitHubでの配置】
1. STEP2確認用として新しく作成したリポジトリを開きます。
2. 「Add file」→「Upload files」を選びます。
3. このフォルダ内の6ファイルをアップロードします。
4. 「Commit changes」を押します。
5. リポジトリの Settings → Pages で公開設定を行います（既に設定済みなら変更不要）。
6. 公開URLの末尾に index.html を付けて開きます。

【確認項目】
1. ページ上部に「STEP2 確認用｜機体管理」と表示される。
2. DB名が DroneDiaryStep2DB、DBバージョンが1と表示される（新規DBの場合）。
3. 機体を登録できる。
4. 機体認証を「あり」にすると区分・番号の入力欄が表示される。
5. 総飛行時間を時間・分で入力できる。分は0〜59。
6. 登録した機体を編集できる。
7. 編集時は編集前データが履歴に保存され、revisionが1増える。
8. 何も変更せず保存した場合は履歴・revision・更新日時を変更しない。
9. 機体削除時は、その機体の編集履歴も同じトランザクションで削除される。
10. STEP1の公開URL・ファイル・データベースに変更がないことを確認する。

【データベースの注意】
新規端末ではDBバージョン1で aircraft と editHistories を作ります。
既存DBのバージョンが1より大きい場合、バージョンを下げません。
必要な保存領域や索引が欠けている場合だけ、端末側の現在バージョンより1上げて追加します。
既存の保存領域を削除・作り直ししません。

【削除判定】
現時点では flightRecords と defects がまだ存在しないため、0件として扱います。
将来どちらかの保存領域が存在する場合は、参照項目が未実装のまま削除しないよう停止します。
工程5・12で該当保存領域を追加する際に削除判定を更新します。

【キャッシュ】
STEP2専用接頭辞 DER_STEP2_CACHE_ を使用します。
STEP1のキャッシュは削除しません。
